راهنمای ادامه‌ی توسعه‌ی Gymbro

نسخه‌ی ۱ · ۱۹ آبان ۱۴۰۵ (۱۰ نوامبر ۲۰۲۶) · برای مهرداد

خلاصه در یک جمله: کد فعلی را کامیت کن، اپ را روی گوشی نصب کن و دو هفته واقعاً با آن تمرین کن؛ بعد هر کار بعدی را دقیقاً از روی فایل docs/roadmap.md و با یک جلسه‌ی کوتاه ایجنت انجام بده.

وضعیت فعلی (چه چیزی آماده است)

  • اپ PWA با Next.js 16 که کاملاً آفلاین روی گوشی کار می‌کند؛ همه‌ی داده‌ها در IndexedDB خود گوشی ذخیره می‌شوند.
  • برنامه‌ها به شکل JSON با یک اسکیمای واحد (برای مربی، هوش مصنوعی و خودت). سه برنامه‌ی قبلی مربی و برنامه‌ی جدید پلن ۴ از قبل داخل اپ هستند.
  • ثبت وزنه و تکرار هر ست، نمایش رکورد جلسه‌ی قبل، پیشنهاد افزایش وزنه، تایمر استراحت و بلوک حرکات اصلاحی در هر جلسه.
  • راهنمای ۱۳۰۰ حرکت با انیمیشن (از دیتاست exercises-dataset).
  • مستندات کامل برای ایجنت‌ها: CLAUDE.md، docs/architecture.md، docs/plan-schema.md، docs/roadmap.md و راهنمای تولید پلن با هوش مصنوعی در docs/ai/.

مرحله‌ی ۱ · همین هفته: اپ را واقعی کن

۱

کامیت و merge. همه‌ی تغییرات فعلی را روی یک برنچ کامیت کن و به main ببر تا هر تغییر بعدی یک diff قابل بررسی باشد.

git checkout -b scaffold
git add -A
git commit -m "Scaffold gymbro: local-first PWA, plan schema, docs"
git checkout main
git merge scaffold

اگر برنچ main وجود ندارد، قبل از آن: git branch -m master main

۲

دیپلوی. یک بار اپ را آنلاین کن تا گوشی بتواند آن را نصب کند. ساده‌ترین راه Vercel است (پروژه را به ریپوی GitHub وصل کن؛ تنظیم خاصی لازم نیست). فقط از برنچ main دیپلوی کن.

۳

نصب روی گوشی و تست واقعی (کار شماره‌ی ۱ در roadmap): در اندروید از منوی مرورگر «Install app»، در آیفون از Share → «Add to Home Screen». یک جلسه شروع کن، سه ست ثبت کن، اپ را ببند، اینترنت را قطع کن و دوباره باز کن. داده‌ها و GIF حرکتی که دیده بودی باید سر جایشان باشند.

۴

نتیجه‌ی تست را بنویس. هر چیزی که خراب بود را در جدول «Next» فایل docs/roadmap.md اضافه کن. استفاده‌ی واقعی باگ‌های مهم را سریع‌تر از هر برنامه‌ریزی نشان می‌دهد.

۵

دو جای خالی را در docs/ai/athlete-context.md پر کن: (الف) بین بهمن ۱۴۰۴ تا آبان ۱۴۰۵ چه تمرینی کرده‌ای؛ (ب) لیست تجهیزات را به چیزی که واقعاً در باشگاهت هست محدود کن. این فایل تنها چیزی است که هوش مصنوعی درباره‌ی تو می‌داند.

مرحله‌ی ۲ · روش انجام هر کار توسعه (با ایجنت‌های سبک)

قاعده‌ی طلایی: هر جلسه‌ی ایجنت فقط یک ردیف از docs/roadmap.md را انجام می‌دهد. معیار پذیرش هر کار همان‌جا نوشته شده است.

متن پیشنهادی برای شروع هر جلسه:

Do task N in docs/roadmap.md. Follow CLAUDE.md.
Finish with `npm run check` and `npm run build` both green,
then update the status column in docs/roadmap.md.
  • ساختار لایه‌ها را ثابت نگه دار: app → features → infra / domain / shared. فایل domain/ فقط TypeScript خالص است و تست دارد.
  • اسکیمای پلن را نشکن: اگر کاری به فیلد جدید نیاز دارد، آن را اختیاری اضافه کن و در docs/plan-schema.md مستند کن.
  • diff را بررسی کن، نه گزارش را: اگر ایجنت گفت همه‌چیز سبز است، خودت قبل از merge دستور npm run check را بزن.
  • هر کار = یک برنچ = یک merge. این باعث می‌شود برگشت از اشتباه ارزان باشد.

مرحله‌ی ۴ · پایان پلن ۴ (اواسط دی ۱۴۰۵): تولید پلن بعدی

۱

آنالیز بدن جدید بگیر و اعداد را به جدول docs/ai/athlete-context.md اضافه کن.

۲

در اپ: Settings → Export all data. فایل خروجی را نگه دار (هم بکاپ است، هم ورودی هوش مصنوعی).

۳

به یک هوش مصنوعی سه فایل بده: docs/ai/plan-generation-guide.md، docs/ai/athlete-context.md، docs/plan-schema.md به‌علاوه‌ی فایل export. خروجی باید فقط یک JSON باشد.

۴

JSON را یا در src/content/plans/ ذخیره کن و به index.ts اضافه کن (تست‌ها اعتبارش را چک می‌کنند)، یا مستقیم در گوشی از Plans → Import وارد کن.

این حلقه (تمرین ← ثبت ← اسکن ← تولید پلن جدید) محصول اصلی است. هر قابلیت جدید را با این سؤال بسنج: «آیا این حلقه را آسان‌تر می‌کند؟»

مرحله‌ی ۵ · بعداً: حالت مربی و چندکاربره

فقط وقتی که حداقل یک دوره‌ی کامل با نسخه‌ی تک‌کاربره تمرین کرده باشی.

  1. هویت: فیلد ownerId به همه‌ی رکوردها (نسخه‌ی ۲ دیتابیس Dexie با upgrade).
  2. همگام‌سازی: پوشه‌ی infra/sync/ با push/pull ردیف‌های تغییر‌کرده بر اساس updatedAt. انتخاب بک‌اند (Postgres/Neon یا BaaS) را اول در یک ADR بنویس.
  3. آپلود پلن توسط مربی: مربی همان JSON را با شناسه‌ی ورزشکار می‌سازد؛ اپ آن را با origin: "coach" می‌کشد و لاگ‌ها برای مربی برمی‌گردند.
  4. دسترسی‌ها: مربی فقط پلن می‌نویسد و لاگ می‌خواند؛ بقیه مال ورزشکار است.

دستورهای پرکاربرد

npm run dev            # اجرای محلی روی http://localhost:3000
npm run check          # typecheck + lint + تست‌ها (قبل از هر merge)
npm run build          # باید همیشه سبز بماند
npm run catalog:build  # بازسازی کاتالوگ حرکات
npm run icons:build    # ساخت دوباره‌ی آیکون‌های PWA
یادآوری مهم: همه‌ی داده‌ها داخل مرورگر گوشی است. هر چند هفته یک بار از Settings خروجی بگیر و جایی امن نگه دار؛ قبل از عوض کردن گوشی حتماً.
